## 6. Implementation steps

1. Add `runInTransaction` in `src/data/transactions/run-in-transaction.ts`. Call `database.transaction('rw', tables, () => body())` and return that promise. Do not check `revision`. Do not read or write `auditEvents`. Do not catch errors. The caller lists every table the body touches. If the installed Dexie typing rejects a readonly array, pass a mutable array of those same table objects. Do not change which tables are included.
2. Reads parse with `parseStored` and the matching schema. A Zod failure throws `PersistenceError` `CORRUPT`, including when a list contains one bad row among valid rows. Do not skip the bad row and do not return a partial list.
   - `getCampaign` and `listCampaigns` use `campaigns`. `listCampaigns` is the only read of a whole table: `campaigns.toArray()`. Campaign rows have no `campaignId`.
   - `getSeason`, `getLeague`, `getClub`, and `getPlayer` load one row with `table.get(id)`. If the row is missing, return `undefined`. If `row.campaignId` is not the requested `campaignId`, return `undefined`. Do not throw `SCOPE` for that read. Then `parseStored`.
   - `listSeasons`, `listLeagues`, `listClubs`, and `listPlayers` use `where('campaignId').equals(campaignId).toArray()`. Do not call `toArray()` on the whole table and then filter in JavaScript.
   - `getActiveSeason` uses `where('[campaignId+status]').equals([campaignId, 'active'])`. Zero rows returns `undefined`. One row is parsed and returned. More than one row throws `CORRUPT`.
   - `listPlayersByClub` uses `where('[campaignId+clubId]').equals([campaignId, clubId]).toArray()`. A player with `clubId: null` is not in that result.
3. Writes are called from inside `runInTransaction`. They do not open their own transaction. They use `add`, never `put`.
   - `insertCampaign` adds the campaign. It does not require a parent row.
   - `insertSeason`, `insertLeague`, `insertClub`, and `insertPlayer` compare `row.campaignId` with the `campaignId` argument. A mismatch throws `SCOPE` with message `Row campaign does not match the scope.` The parent campaign row does not need to exist yet. `P02-G04` inserts the club and the season before the campaign row.
   - `insertClub`: when `leagueId` is not `null`, load that league by id. If it is missing or its `campaignId` is different, throw `SCOPE` with message `League is not in this campaign.` `leagueId: null` does not look up a league.
   - `insertPlayer`: when `clubId` is not `null`, load that club by id. If it is missing or its `campaignId` is different, throw `SCOPE` with message `Club is not in this campaign.` `clubId: null` is a free agent and does not look up a club.
   - `insertSeason`: when `status` is `'active'`, query `[campaignId+status]` for `'active'`. If a row already exists, throw `SCOPE` with message `This campaign already has an active season.` A `closed` season does not run that check. Then query `[campaignId+ordinal]` for `season.ordinal`. If a row already exists, throw `DUPLICATE` with message `This campaign already has that season ordinal.`
   - Wrap every `add` in `try/catch`. When the caught error is `Dexie.ConstraintError`, throw `new PersistenceError('DUPLICATE', 'A row with this id already exists.')`. Rethrow anything else. A repeated primary key must not overwrite the stored row.
4. `updateCampaign` re-reads by `campaign.id`. If the id is absent, return without writing. If the stored row fails `parseStored`, throw `CORRUPT` and do not write. Otherwise call `campaigns.update(id, changes)` where `changes` is every field except `id`. Do not call `put` or `add`. Do not add `1` to `revision`. The number in the object is the number that gets stored.
5. No repository function writes `auditEvents` or any table other than its own, except the link lookups in steps 3. No function calls `Date.now`, `new Date`, or `Math.random`. Do not add that ESLint ban in this guide.
6. Add `src/test/fixtures/campaign.ts` by parsing the objects in §7 with `campaignSchema`, `clubSchema`, and `seasonSchema`. Export the parsed values, not the raw inputs.
7. Add `src/test/repositories.test.ts` as specified in §7. Build players and leagues in the test with `playerSchema.parse` and `leagueSchema.parse`. Use one database name, `'touchline-os-test'`. `afterEach` awaits `deleteDatabaseForTests('touchline-os-test')`.

### Cases

Each case is its own `it`. Assert `PersistenceError` and `code`. Do not assert the message text.

- Insert both campaigns, both clubs, and both seasons in one `runInTransaction`. `listCampaigns` contains both ids. `listClubs(campaignA.id)` contains `club-a` and not `club-b`. `listSeasons(campaignB.id)` contains `season-b` and not `season-a`. `getCampaign(campaignA.id).revision` is `0`. `auditEvents.toArray()` is empty.
- Insert the player for campaign A. `getPlayer(campaignA.id, player.id)` returns that player and `marketValueCents` is `null`. `getPlayer(campaignB.id, player.id)` is `undefined`. `listPlayers(campaignB.id)` is empty. `database.players.get(player.id)` is still defined.
- Insert the same player id a second time. The call throws `DUPLICATE`. `listPlayers(campaignA.id)` still has one row, and the stored name is still `Amina Cole`.
- Insert a second season for campaign A with id `season-a2`, ordinal `2`, and status `closed`. It is stored. `listSeasons(campaignA.id)` has both ids. Then insert id `season-a3`, ordinal `3`, status `active`. That call throws `SCOPE`, and the active season id is still `season-a`. Then insert id `season-a4`, ordinal `1`, status `closed`. That call throws `DUPLICATE`, and ordinal `1` is still `season-a`.
- Insert a player whose `campaignId` is `campaign-a` and whose `clubId` is `club-b`. The call throws `SCOPE`. `listPlayers(campaignA.id)` does not contain that new id, and `database.players.get` of that id is `undefined`. Use a new id `player-cross` so this is not the duplicate-id case.
- Insert a player with `clubId: null` and id `player-free` for campaign A. It is stored. `listPlayersByClub(campaignA.id, clubA.id)` does not include `player-free`. `getPlayer` does.
- Insert league A and league B. Insert a club id `club-linked` for campaign A with `leagueId` `league-a`. It is stored. Insert club id `club-foreign` for campaign A with `leagueId` `league-b`. That call throws `SCOPE`, and `getClub(campaignA.id, 'club-foreign')` is `undefined`.
- Call `insertSeason` with `campaignA.id` and a season object whose `campaignId` is `campaign-b` and whose id is `season-mismatch`. The call throws `SCOPE`. That id is not stored.
- `getClub(campaignB.id, clubA.id)` is `undefined`. `getSeason(campaignA.id, seasonB.id)` is `undefined`.
- `updateCampaign` with a campaign id that was never inserted leaves `listCampaigns` unchanged. `updateCampaign` of campaign A with name `Riverside Athletic` and `revision` still `0` stores that name and leaves `revision` at `0`. `auditEvents` stays empty.
- Store a player row for campaign A that has no `source`, using the `as unknown as Player` insert from `src/test/database.test.ts`. Also store the valid `player-a` in that campaign. `getPlayer` for the bad id throws `CORRUPT`. `listPlayers(campaignA.id)` throws `CORRUPT` and does not return `player-a`.

### Failure cases that must keep failing

- A list implemented as `toArray()` plus a JavaScript `campaignId` filter can pass the isolation test and still violate this guide. Use the `where` calls in §6.
- `put` on a repeated id overwrites `Amina Cole`. The duplicate test forbids that.
- Treating `marketValueCents: null` as `0` fails the round-trip assertion.
- Requiring the parent campaign row to exist before `insertClub` or `insertSeason` is not part of this guide. Those inserts must succeed when the campaign row is not there yet.
- An active-season check that runs outside the test’s `runInTransaction` is not the check this guide specifies. The test calls `insertSeason` from inside `runInTransaction`.

## 12. Handoff

`P02-G04` may call:

- `runInTransaction`
- `insertCampaign`, `updateCampaign`, `insertClub`, `insertSeason`, `insertPlayer`
- `getCampaign`, `listCampaigns`, `getPlayer`, `listPlayers`, `getActiveSeason`, `listClubs`

`updateCampaign` stores the `revision` it is given. The command adds one before the call. A repository `SCOPE` error stays `SCOPE` here. `P02-G04` maps that code to `CommandResult` `VALIDATION`. A Dexie constraint mapped by these inserts is already `PersistenceError` `DUPLICATE`.

`P02-G04` adds `src/data/clock.ts`, `src/data/ids.ts`, and the ESLint ban on `Date.now`, `new Date`, and `Math.random` for `src/data/repositories/**`, `src/data/commands/**`, and `src/data/transactions/**`, excluding the clock and id modules.

Known limitations this guide leaves on purpose:

- No `runCommand`, no audit write, and no revision increment inside the repository.
- Contracts, constitutions, ledger rows, and the other tables have no repository.
- There is no delete. A missing campaign id on `updateCampaign` is a no-op, not `NOT_FOUND`. The command returns `NOT_FOUND`.
- The shell still cannot save a campaign, and a normal page load does not open `touchline-os`.
